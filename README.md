# 基于 RISC-V 的 FPGA 边缘体感游戏平台

本项目将乱序 RISC-V 处理器、D1 人体检测、P2 姿态估计、摄像头采集、2D GPU 和双屏显示集成在紫光同创 PG2L200H FPGA 上。处理器运行游戏控制和应用逻辑；视觉模型经 INT8 量化并由片上硬件执行。

## 设计与结果

| 项目 | 配置或结果 | 口径 |
|---|---|---|
| 独立 CPU 性能 | 7.3609 CoreMark/MHz，169.714 MHz | 独立计分镜像，13,000 次、CRC 通过 |
| 整机 CPU | 157.5 MHz | 体感游戏平台整机配置 |
| 视觉链路 | 约 60 次/秒 | 指定板上观察窗口的流水线计数 |
| D1 模型 | `s16_d1` | 单人体检测，INT8 |
| P2 模型 | PlainPose `s16_hx_r96` | 288×192 输入，12 个关节，INT8 |
| 显示 | HDMI 1280×720、LCD 1024×600 | 摄像头和图形画面 |

独立 CPU 计分、整机运行、视觉流水线计数和显示帧率属于不同测量范围。D1 与 P2 分别加载 COCO 预训练检查点，再使用 OV5640 数据微调；P2 使用 PlainPose `s16_hx_r96` 配置。YOLOX-x 和 RTMPose-x 用于离线教师标注，不是板端运行的模型。

## 系统结构

```text
OV5640 摄像头
      │
      ├── DVP 采集 ── D1 人体检测 ── ROI 裁剪 ── P2 姿态估计 ── 12 个关节点
      │                                                        │
      │                                             RISC-V CPU ── 动作识别与游戏
      │                                                        │
      └── DDR3 视频三缓冲 ── 摄像头画面          2D GPU ── 游戏帧缓冲
                              └──────────── 图层合成 ────────────┘
                                             │
                                       HDMI + LCD
```

开发板为 **MES2L676-200HP-MINI**，FPGA 为 **PG2L200H-6/FBB676**。系统通过 OV5640 获取视频，GT911 提供最多五点触摸，DDR3 保存程序和图像数据，SPI Flash 保存位流，SD 卡保存程序、资源和存档。UART、JTAG 和 ILA 分别用于调试输出、配置验证和内部信号观测。

## 时钟与存储映射

| 时钟域 | 工作频率 | 主要功能 |
|---|---:|---|
| CPU | 157.5 MHz | O2 内核、Cache、处理器侧外设 |
| AI | 121.5 MHz | 检测、裁剪、姿态与结果发布 |
| GPU | 约 74.769 MHz | 图形命令与像素绘制 |
| DDR 用户侧 | 125 MHz | DDR 请求和响应 |
| HDMI 像素 / 串行 | 74.25 / 371.25 MHz | 720p60 扫描与 TMDS 输出 |
| LCD 像素 | 51.2 MHz | 1024×600 扫描 |
| 摄像头像素时钟 | 96 MHz | DVP 采样 |

CPU 将片内 SRAM 映射到 `0x80000000` 起，DDR 软件窗口从 `0x80020000` 起；UART 和 GPIO 分别位于 `0x10000000` 和 `0x10001000`，视觉加速器使用 `0x10008000`—`0x1000FFFF` 窗口。系统使用异步 FIFO 或整组请求/确认处理跨时钟数据；寄存器和接口定义可在对应 RTL 中查看。

## 处理器

O2 内核支持 `RV32I + Zmmul + Zbc + Zicsr + Zifencei`，运行于机器模式；乘法由硬件支持，除法由软件库完成。内核采用 14 级逻辑流水线，每周期最多分派、提交各两条指令，配合三路执行队列、寄存器重命名和按序提交。

| 模块 | 配置 |
|---|---|
| 前端 | 16 B 取指块、32 项取指队列 |
| 乱序状态 | 32 项 ROB、64 个物理寄存器、8 个分支检查点 |
| 执行队列 | IQ0、IQ1、IQM 各 8 项 |
| 访存 | 8 项存储队列、8 项加载队列；依赖推测、转发和重放 |
| 分支预测 | NLP、TAGE、双模预测、间接 BTB、8 项 RAS |
| I-Cache / D-Cache | 各 16 KiB、两路组相联、32 B 行，8 拍突发 |
| 异常与中断 | 精确同步异常；机器外部、软件和定时器中断 |

## 视觉模型与流式加速

板端采用两级 INT8 视觉模型：

| 模型 | 配置 | 输入与输出 | 运算量 |
|---|---|---|---:|
| D1 单人体检测 | `d1_ov_teacher`，`s16_d1` | 96×160 RGB 输入；输出人体中心热图与检测框 | 37.1 MMAC/帧 |
| P2 人体姿态估计 | `p2f_r96_288_ft`，PlainPose `s16_hx_r96` | 288×192 RGB 裁剪输入；输出 12 个关节的热图与偏移 | 267.5 MMAC/帧 |

模型在 COCO 人体数据上预训练，结合 OV5640 实拍数据微调并导出 INT8 权重。YOLOX-x 和 RTMPose-x 用于离线教师标注；板端运行的模型是上表中的 D1 与 P2。模型训练代码、已保存的检查点和历史训练参数位于 [`training/`](training/)；数据与环境要求见[模型归档说明](training/final_models/README.md)。

D1 检测框由 CPU 解码为 ROI，硬件进行双线性裁剪后送入 P2。P2 输出 12 个关节，硬件生成 13 字摘要，软件校验后发布坐标并进行平滑。逐层启动队列、两帧上下文和结果租约支持连续处理并保护结果一致性。

P2 与 D1 分别配置 410 和 110 个 PE，AI 时钟为 121.5 MHz；按 520 个 PE 计算的理论峰值为 63.18 GMAC/s。在 60 次/秒工作量下，按两模型 MAC 数计算的有效吞吐约为 18.28 GMAC/s。该计算值与板上观察窗口的计数、RTL 仿真延迟分别采用不同口径。

PCK@0.2 为预测关节点与教师参考点的距离不超过 0.2 倍躯干尺度的比例。腕、肘、膝、踝和全部关节的离线结果分别为 0.956、0.985、0.971、0.966、0.977；模型和环境配置见[模型归档](training/final_models/README.md)。

### 数据流和量化

检测输入先采样为 160×90，再上下补黑形成 160×96；CPU 对检测框按 2:3 宽高比和 1.25 倍外扩形成 ROI。裁剪输出 192×288 图像，经 P2 输出 18×12 网格上的热图与偏移。训练使用带符号 INT8 权重和无符号 8 位激活，卷积累加后按层移位重量化。

硬件通过帧上下文、双结果存储体及 CPU 读租约保证结果身份和内容一致。正常情况下，CPU 读取 12 个关键点摘要及 1 个标签字；摘要能力、标签或帧号不匹配时回退至原始输出读取。游戏消费经有效性检查和 One Euro 滤波的姿态结果。

## 整机资源与时序

| 资源 | 已用 / 总量 | 占比 |
|---|---:|---:|
| LUT | 95,831 / 159,800 | 60.0% |
| FF | 122,666 / 319,600 | 38.4% |
| 分布式 RAM 计数 | 9,859 / 39,500 | 25.0% |
| DRM | 403 / 415 | 97.1% |
| APM | 555 / 740 | 75.0% |

上述为设备映射阶段的整机资源，包含 CPU、AI、GPU、视频和平台逻辑。R82x seed 4 已完成原版布局布线及内部静态时序分析，120 条内部时序汇总通过；Slow Setup 下 CPU、AI、GPU、DDR 相关路径 WNS 分别为 +0.186、+0.322、+1.515、+0.369 ns。52 组最大偏斜约束通过，最小裕量 +2.737 ns。

整机 CPU、AI、GPU、DDR 用户侧时钟分别为 157.5、121.5、约 74.769、125 MHz；异步 FIFO 和整组握手用于跨时钟传输，复位在目标时钟域同步释放。

## 仓库内容

- `hardware/`：整机 CPU、视觉、GPU、摄像头、存储和显示逻辑，以及约束和部署权重 ROM。
- `firmware/`：启动程序、体感和触摸应用、姿态显示和 NES 模拟器的软件适配。
- `cpu_standalone/`：独立 CPU、CoreMark 源码和构建工具。
- `fusion_cpu1575/`、`games_cpu1575/`：平台固件，以及 PAL、DOOM 等移植代码。
- `training/`：训练、量化、模型导出和已保存的模型参数。
- `release/r82x_s4_ai31_20261022/sdcard/`：可公开的 SD 应用程序与资源；并非完整 SD 卡镜像。
- `scripts/`、`tools/`：工程准备和软件重建入口。
